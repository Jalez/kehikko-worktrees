Kind: feature

- **Worktrees, a new module.** Every git worktree of your projects in one place: three charts — the disk they take by project or repository, how much is reclaimable, kept or active, and the biggest ones — and, with room, the list with each worktree's branch, folder, last activity, size, pull or merge request, uncommitted or unpushed work, and whether an agent session works in it.
- **Merged worktrees clean themselves up.** "Clean up merged worktrees automatically" in the header, on by default on this computer, removes a worktree and its local branch once its request is merged and its last commit is in the merged branch, with no changes, nothing unpushed and no session working in it. Anything else is listed as kept, with the reason. Every removal is logged.
- **Quick actions.** Clean up merged (in the footer, beside "N worktrees · X GB · Y GB reclaimable"), Remove on a row (asks again first), Rescan, Prune, and Open in Finder.
- **Agents work in worktrees.** On a kehikko Worktrees is on, agent sessions and their subagents are refused file edits in a project's main checkout and in installed module folders, and told how to make a worktree; `bun run register` is refused.

## For agents

- On a kehikko with Worktrees, edits in a main checkout or under Kehikot's installed modules are refused: make a worktree with `git worktree add ../<repo>-worktrees/<branch> -b <branch> origin/main` and work there, one branch per task. It is removed once its PR is merged.
- The `worktrees` tool lists every worktree with its size, request and whether it would be cleaned up. It is read-only.
